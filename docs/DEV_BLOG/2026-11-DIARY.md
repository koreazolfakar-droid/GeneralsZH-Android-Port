# November 2026 development diary

## 2026-11-05 — measured audio fallback reads

Engine 3679 device logs report 11,754 cache misses, 1,414 native WAV
successes, 1,268 evictions and zero reported admission drops across 1,072
windows. The remaining misses combine FFmpeg fallback and failed opens; the
current counters cannot separate them. The decoder probe previously read an
entire non-WAV file before rewinding and reading it again via FFmpeg. Probe
only the 12-byte WAV header for non-`.wav` filenames; ordinary WAV assets
keep their original single-read path, including archive-backed files.
Per-window diagnostics now separate missing files, successful FFmpeg fallback
and decoder-open/decode failures, without changing existing log fields.
Decoded PCM bytes held by cached buffers and active-voice evictions are now
tracked separately from the legacy encoded-byte budget. Driver allocation and
streaming buffers are not included; cache policy and maximum remain unchanged.
The perf window also counts streams observed stopped with queued data outside
pause/EOF; this is a starvation signal, not proof of audible underrun.
A production-code ASan/UBSan fixture checks non-WAV, WAV and short inputs;
it is mandatory in native builds and OTA preparation. Device audio, battle,
latency and FPS comparisons remain required. No APK changes.

## 2026-11-05 — continue PR #45 with upload reuse and catch-up boundary guards

Reviewed the eight existing branch commits and successful exact-source native run
41971063496 (engine 3676, source 0c97b711, both rates). Reproduced unchanged
static-terrain DISCARD transfers and catch-up continuing after game-mode changes.
Skip a terrain DISCARD only when the entire initialized prefix matches the last
queued snapshot. Changed vertices outside the lock, uninitialized prefixes,
dynamic storage, FIFO capture and Mali index/fence behavior retain their paths.
Catch-up now requires an actual regular tick and rechecks game/network/replay
state and its deadline after message processing, before admitting another tick.
Fresh script freeze and speed/time-scale changes also stop the current recovery
loop, including before FramePacer cached flags have been refreshed.

the waiting-flag fast path could skip the completion notification. Reproduced
with one sleeping main thread after the worker exited; the original 100,000-race
fixture timed out after 45 seconds. Always take the waiter's mutex before
notifying. The repaired fixture completes in 2.77 seconds and also passes
ThreadSanitizer. Expanded the regular CI fixture from 500 to 10,000 races.
GPU fences, command ordering, buffer ownership and Mali index handling are intact.

Added production-orchestration ASan/UBSan fixtures for both 30/60Hz engines and
made these plus the existing budget fixture mandatory in native reports and OTA
preparation. Extended the engine-only commit marker's APK suppression to perf
branches. No APK packaging is authorized. Host checks and native validation are
recorded in the continuation report; device performance, real replay/save/input
and multiplayer checks still require a device. Keep PR #45 draft and do not
publish while those acceptance gates are unresolved.

## 2026-11-05 — bounded offline simulation recovery and VBO source attribution

Post-3667 device logs show a 60-Hz configured engine advancing around 46 game
ticks/s during a 46-FPS TEOD battle, with speedCatchUpSteps=0. Zero Hour's
existing faster-than-normal catch-up excluded ordinary/uncapped offline play.
On Android, the engine now accrues limited normal-speed time debt and executes
up to three extra ordered offline ticks per rendered frame within a 6-ms
CPU budget, without changing network/replay/paused/slow-speed scheduling.
The original high-speed catch-up and core D3D lock semantics remain intact.

The GLES backend now reports full vertex-buffer upload owners, upload causes,
and reasons terrain snapshot comparisons are bypassed, to isolate steady-state
12-MB/frame full + 10-MB/frame terrain uploads. Regression coverage extends
30/60-Hz pacing and retains extraction-based GLES upload tests.

This work lives in a separate integration branch. Host-budget model checks
passed with UBSan. Complete engine builds, device frame-time comparisons,
save/replay tests and verified OTA publication remain outstanding.
