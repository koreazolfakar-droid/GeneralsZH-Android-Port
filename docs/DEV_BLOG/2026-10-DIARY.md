# October 2026 Development Diary

## Overview

Android rendering performance and Project X Re compatibility work.

## 2026-10-02 — Battle-load performance pass

- Analyzed a full Project X Re battle session that remained crash-free but fell to about 14 fps near peak combat.
- Corrected the GLES diagnostic wording: the sorting bucket is not particles alone; it also contains decals and other sorted alpha geometry.
- Added per-category geometry telemetry (vertices and primitives), peak-frame draw attribution, and VB/IB/UP upload pressure counters so draw submission, geometry load, and synchronization pressure can be separated in the next device log.
- Added Android GLES/ANGLE-only adaptive HLOD pressure. It scales render-object screen size from 1.00 at VeryHigh to 0.55 at Low dynamic LOD, without changing game logic, collision, object state, AI, commands, damage, or lockstep simulation.
- Kept Vulkan/DXVK and desktop HLOD behavior unchanged until separately measured.
- Did not re-enable the legacy predictive LOD optimizer; the existing display code explicitly leaves it disabled and notes a historical particle-system issue.
- No GitHub Actions workflow was triggered. Android validation still requires the repository's local dual-Hz build and a real-device battle replay/test.
